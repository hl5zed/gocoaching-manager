# 피코치(coachee) 중심 모바일 우선 UI 리뉴얼 초안

> **문서 성격**: 설계/분석 초안. 이 문서는 코드를 수정하지 않으며, 실제 구현 전 단계의 제안서다.
> **대상 사용자**: 피코치(coachee). 코치·코치메이커·관리자 화면은 이번 범위에서 제외(권한 연동만 고려).
> **전제**: 기존 Next.js App Router + TypeScript + Tailwind + Supabase 웹 프로그램을 그대로 활용. 이후 PWA로 확장 가능하도록 설계.
> **작성 기준일**: 2026-06-16 / 날짜·실행률 기준 타임존: **Asia/Bangkok** (DB 기본값 확인됨)

## 0. 현재 구조 분석 요약 (실제 코드 기준)

리뉴얼 설계는 기존 DB·라우트 구조 위에서 이루어진다. 코드 확인 결과 핵심 자산은 다음과 같다.

**이미 존재하는 피코치 관련 라우트**

- `src/app/coachee/` — 피코치 메인, 리포트
- `src/app/my-coaching/` — goals, weekly-log, feedback, records(daily/monthly), moksilgi(목실기), spiritual-companion

**이미 존재하는 핵심 테이블 (이번 설계가 재사용해야 할 Single Source of Truth)**

| 테이블 | 역할 | 주요 필드 |
|---|---|---|
| `moksilgi_plans` | 삶의 방향 + 목표 기획안(목실기) | mission_statement, vision_statement, **core_values_json**, main_goal |
| `moksilgi_goal_areas` | 4영역 정의 | **area_key**('spiritual·intellectual·physical·social'·other), area_title, sort_order |
| `moksilgi_detail_goals` | 영역별 세부 목표 | plan_id, area_id, title |
| `moksilgi_monthly_records` | 월간 영역별 실행 기록 | **daily_checks_json**, weekly_counts_json, achievement_rate, year, month |
| `moksilgi_monthly_summaries` | 월간 영역별 실행률 집계 | spiritual_rate, intellectual_rate, physical_rate, social_rate, total_rate, average_rate |
| `daily_records` | 하루 기록 | title, reflection, practice, prayer_request, visibility, **shared_with_coach** |
| `weekly_logs` | 주간 로그 | gratitude, prayer_request, progress_summary, difficulty, message_to_coach, status(draft/submitted) |
| `monthly_reflections` | 월간 회고 | summary, growth_points, difficulty, next_month_plan, shared_with_coach |
| `coach_feedback` | 코치 피드백 | weekly_log_id, feedback_text, encouragement, next_step |
| `coaching_relationships` | 코치-피코치 연결 | coach_profile_id, coachee_profile_id, status |
| `spiritual_entries` / `prayer_requests` | 영적 동반 기록 | content, mood, request_text, answered_text |

**가장 중요한 발견 (설계의 출발점)**

1. **4영역은 이미 `area_key`로 존재한다** — spiritual(영적)·intellectual(지적)·physical(신체적)·social(사회적). 새 enum을 만들 필요 없음.
2. **미션/비전/핵심가치/목표는 `moksilgi_plans`에 이미 있다** — "나의 성장" 화면은 신규 테이블 없이 이 테이블을 읽으면 됨.
3. **"일일 체크"의 데이터는 `moksilgi_monthly_records.daily_checks_json` 안에 들어있다** — 즉 현재는 *월 단위 레코드의 JSON 안에 일별 체크가 묻혀 있는* 구조. 모바일의 "오늘 체크"를 빠르게 쓰려면 이 부분이 **가장 큰 데이터 구조 과제**(아래 E·F 참조).
4. **`daily_records`에는 '감사한 일' 전용 필드가 없다** — gratitude는 `weekly_logs`에만 있음. 요구사항의 "오늘 기록 > 감사한 일"은 필드 매핑 조정이 필요.
5. **공유/비공개 구분은 이미 있다** — `visibility` + `shared_with_coach` 컬럼 재사용 가능.

> 결론: 이번 리뉴얼은 **신규 DB를 최소화하고 기존 moksilgi/records 구조를 모바일 UI로 재배치**하는 것이 핵심이다. enum·저장 값은 변경하지 않고 화면 표시만 한국어 우선으로 구성한다.

## A. 전체 리뉴얼 방향 요약

### A-1. 왜 모바일 우선인가
피코치의 핵심 행동은 "매일 1~3분, 오늘 목표 확인 → 체크 → 짧은 기록"이다. 이 행동은 책상이 아니라 손안에서 일어난다. 현재 UI는 사이드바(`ShellLayout`/`SidebarNav`) 기반의 데스크톱 관리자형 레이아웃이라 피코치의 일상 사용에는 마찰이 크다. 모바일 우선 + 하단 탭으로 전환하면 매일의 진입 비용이 크게 낮아진다.

### A-2. 왜 피코치 중심 UI가 별도로 필요한가
관리자·코치 화면은 "여러 사람을 관리"하는 밀도 높은 표 중심 UI가 맞지만, 피코치 화면은 "나 한 사람의 오늘"에 집중하는 단순·따뜻한 UI여야 한다. 같은 컴포넌트를 공유하되 **피코치 전용 셸(하단 탭 레이아웃)** 을 분리하는 것이 바람직하다.

### A-3. PWA 확장 가능성
기존 Next.js 구조를 그대로 두고, 추후 `manifest.json` + 서비스워커(예: `next-pwa` 또는 App Router 네이티브 방식)만 추가하면 홈 화면 설치·오프라인 캐시·푸시 알림으로 확장 가능하다. 이번 단계에서는 **PWA를 전제로 한 레이아웃 규칙**(하단 탭, safe-area 여백, 단일 컬럼)만 미리 지킨다. 실제 PWA 설정은 4단계(F 참조).

### A-4. 기존 자산을 살리는 원칙
- 기존 `src/components/ui`(Button, Card, Badge, ProgressBar, Icon, Input)와 디자인 토큰(`--brand-*`, `--surface-*`, `--ink-*`)을 **그대로 재사용**.
- 라우트는 기존 `my-coaching/*`를 유지하고, 그 위에 모바일 셸만 새로 입힌다(presentational 레이어 추가).
- 인증/role 분기/Supabase 쿼리 의미/DB 스키마는 **건드리지 않는다**(CLAUDE.md 15항 준수).

## B. 피코치 모바일 화면 구조도

### B-1. 하단 탭 구조 (5탭)

```
┌─────────────────────────────────────────┐
│            (화면 콘텐츠 영역)              │
│                                           │
├──────┬──────┬──────┬──────┬──────────────┤
│ 오늘  │ 체크  │ 기록  │ 리포트 │   성장      │
│ 🏠   │ ✓    │ ✍️   │ 📊    │   🌱        │
└──────┴──────┴──────┴──────┴──────────────┘
```

| 탭 | 라벨(ko) | 연결 화면 | 핵심 동작 |
|---|---|---|---|
| 1 | 오늘 | 오늘의 목표(홈) | 오늘 4영역 목표·실행률 확인, 빠른 진입 |
| 2 | 체크 | 오늘 실행 체크 | 4영역 To-do 체크, 실행률 즉시 갱신 |
| 3 | 기록 | 오늘 기록 | 감사·배움·기도·실행 메모 작성 |
| 4 | 리포트 | 주간/월간 리포트 | 흐름·그래프·코치 피드백 확인 |
| 5 | 성장 | 나의 성장 | 미션·비전·핵심가치·장기목표 확인 |

**탭 설계 근거**: 매일 쓰는 동사(오늘·체크·기록)를 앞쪽에, 돌아보는 동사(리포트·성장)를 뒤쪽에 배치. 5개는 모바일 하단 탭의 권장 상한이라 라벨 가독성이 유지된다.

**대안 검토**: "체크"와 "기록"을 하나의 "오늘 하기" 탭으로 합쳐 4탭으로 줄이는 안도 가능(체크 완료 → 같은 화면에서 기록으로 스크롤). 단계적 입력 흐름을 더 부드럽게 하려면 4탭, 기능을 명확히 분리하려면 5탭. **초안 권장: 5탭으로 시작하고 사용 데이터를 본 뒤 4탭 통합을 검토.**

### B-2. 화면 이동 흐름

```
[오늘의 목표] ──"오늘 기록하기"──▶ [오늘 실행 체크] ──저장──▶ [오늘 기록] ──저장──▶ [오늘의 목표]로 복귀
     │                                                                              
     ├─"주간 리포트 바로가기"──▶ [주간 리포트] ──▶ [코치 피드백 상세]
     └─"월간 리포트 바로가기"──▶ [월간 리포트] ──"월간 회고 작성"──▶ [월간 회고 폼]

[나의 성장] ──항목별──▶ [미션/비전/핵심가치/목표 수정] (편집 가능 여부는 권한·잠금 규칙 따름)
```

피코치의 "매일 루틴"은 **오늘 → 체크 → 기록 → 오늘 복귀**의 짧은 루프로 닫히게 설계한다. 리포트와 성장은 주/월 단위의 돌아보기 진입점.

## C. 핵심 화면별 UI 초안

각 화면은 ① 목적 ② 주요 구성 요소 ③ 모바일 레이아웃 ④ 버튼/카드/그래프 ⑤ 사용자 행동 흐름 ⑥ 필요한 데이터 ⑦ 코딩 시 주의사항 순으로 정리한다.

### C-1. 오늘의 목표 (탭: 오늘 / 홈)

**① 목적**
오늘 해야 할 4영역 목표를 한눈에 확인하고, 오늘의 전체 실행률을 즉시 파악한다. 모든 일일 루틴의 진입점.

**② 주요 구성 요소**
- 상단 인사 + 오늘 날짜(Asia/Bangkok 기준, 예: "6월 16일 화요일")
- 오늘 전체 실행률 링/바 (예: 75% · 4개 중 3개)
- 4영역 목표 카드 (영적·지적·신체적·사회적) — 각 카드에 영역 색·아이콘, 오늘 세부목표 요약, 진행 상태(완료/미완료/일부)
- 큰 CTA "오늘 기록하기" 버튼
- 보조 링크: "주간 리포트", "월간 리포트"

**③ 모바일 레이아웃**
```
┌──────────────────────────────┐
│ 안녕하세요, ○○○님 👋          │
│ 6월 16일 화요일                │
├──────────────────────────────┤
│   ◍ 오늘 실행률  75%          │
│   오늘 4개 중 3개 완료         │
├──────────────────────────────┤
│ ┌──────────┐  ┌──────────┐   │
│ │🙏 영적    │  │📖 지적    │   │
│ │ 새벽기도   │  │ 독서 30분 │   │
│ │ ✅ 완료    │  │ ⬜ 미완료 │   │
│ └──────────┘  └──────────┘   │
│ ┌──────────┐  ┌──────────┐   │
│ │💪 신체적  │  │🤝 사회적  │   │
│ │ 걷기      │  │ 안부전화   │   │
│ │ ✅ 완료    │  │ ✅ 완료   │   │
│ └──────────┘  └──────────┘   │
├──────────────────────────────┤
│ [   오늘 기록하기   ]  (큰버튼)│
│  주간 리포트 ›   월간 리포트 › │
└──────────────────────────────┘
```
- 단일 컬럼 스크롤, 4영역은 2×2 카드 그리드(좁은 화면에선 1열로 자동 전환).

**④ 버튼/카드/그래프**
- 실행률: 원형 progress ring(숫자 강조) 또는 기존 `ProgressBar` 활용.
- 영역 카드: 좌측 색 바/아이콘 + 상태 배지(`Badge` 재사용).
- CTA: full-width, 높이 48px 이상.

**⑤ 사용자 행동 흐름**
홈 진입 → 실행률 확인 → 미완료 카드 탭(해당 영역 체크로 이동) 또는 "오늘 기록하기" → 체크 화면.

**⑥ 필요한 데이터**
- 오늘 날짜(타임존 변환): 사용자 profile timezone → 없으면 org → 없으면 `Asia/Bangkok`.
- 4영역 + 오늘 세부목표: `moksilgi_goal_areas` + `moksilgi_detail_goals`.
- 오늘 체크 상태: `moksilgi_monthly_records.daily_checks_json`의 오늘 날짜 키.
- 오늘 실행률: 체크된 영역 수 / 활성 영역 수 (계산 기준은 E·아래 참조).

**⑦ 코딩 시 주의사항**
- 실행률 계산 로직을 클라이언트와 서버가 동일하게 쓰도록 **공용 유틸**로 분리(중복 계산 방지).
- 날짜 키는 반드시 사용자 로컬 날짜(Asia/Bangkok)로 생성. UTC 자정 경계 버그 주의.
- 세부목표가 0개인 신규 피코치를 위한 **빈 상태(empty state)** ("아직 목표가 없어요 → 나의 성장에서 추가") 필수.

### C-2. 오늘 실행 체크 (탭: 체크)

**① 목적**
4영역 To-do를 가장 적은 탭으로 체크한다. 하루 입력의 핵심.

**② 주요 구성 요소**
- 4영역별 체크 항목 리스트(영역 헤더 + 세부목표 체크박스)
- 완료/미완료 상태 시각화
- "오늘 4개 중 3개 완료" 직관 문구
- 저장 버튼(또는 자동 저장)

**③ 모바일 레이아웃**
```
┌──────────────────────────────┐
│ 오늘 실행 체크   6/16(화)      │
│ 오늘 4개 중 3개 완료 ▓▓▓░     │
├──────────────────────────────┤
│ 🙏 영적                        │
│  ☑ 새벽기도                    │
│  ☐ 말씀 묵상                   │
│ 📖 지적                        │
│  ☑ 독서 30분                   │
│ 💪 신체적                      │
│  ☑ 걷기 8000보                 │
│ 🤝 사회적                      │
│  ☐ 가족과 식사                 │
├──────────────────────────────┤
│ (자동 저장됨 · 방금)           │
└──────────────────────────────┘
```

**④ 버튼/카드/그래프**
- 큰 터치 영역의 체크박스(행 전체 탭으로 토글).
- 상단에 미니 진행 바 + 카운트.

**⑤ 사용자 행동 흐름**
체크 토글 → (자동 저장) → 상단 카운트·실행률 실시간 갱신 → 완료 시 "기록 남기기" 유도.

**⑥ 자동 저장 제안**
- **권장: 자동 저장(디바운스 ~800ms)** + "저장됨" 토스트. 모바일에서 저장 버튼을 누르지 않고 나가는 이탈을 방지.
- 네트워크 실패 시 로컬 임시 보관 후 재시도(낙관적 UI). 명시적 "저장" 버튼은 보조로 유지(접근성/안심용).

**⑦ 실행률 계산 방식 제안**
- 기본: `오늘 실행률 = 오늘 체크 완료한 세부목표 수 / 오늘 대상 세부목표 수 × 100`.
- 영역 균형을 강조하려면: `영역별 완료 여부(0/1) 평균` 방식도 가능. **초안 권장: 세부목표 기준 단순 비율**(설명이 쉽고 moksilgi 구조와 일치).
- 표시는 숫자(%) + 미니 바를 함께.

**⑦ 코딩 시 주의사항**

- enum 값(area_key 등) 변경 금지, 화면 라벨만 한국어.

**⑦ 코딩 시 주의사항**
- **mission/vision/core_values 필드 구조를 추정하지 말 것**(CLAUDE.md 15항). `core_values_json` 형태를 실제 데이터로 확인 후 렌더.
- 편집은 기존 저장 흐름·status 규칙을 따른다. 새 저장 로직 신설 금지.

## D. 디자인 스타일 가이드 초안

### D-1. 전체 분위기
따뜻하고 차분한 "성장 동반자" 톤. 관리자 시스템의 딱딱함을 덜고, 여백·둥근 모서리·부드러운 그림자로 안정감을 준다. 청소년~성인 모두에게 중립적이고 신뢰감 있는 인상.

### D-2. 색상 방향 (기존 토큰 재사용)
- 브랜드 기본: 기존 `--brand-500: #14a583`(틸 그린), `--brand-600: #0f6e56`. 성장·생명·신뢰의 그린 계열 유지.
- 배경: `--surface-app: #f6f8f7`(연한 오프화이트), 카드 `--surface-card`.
- 텍스트: `--ink-strong / base / muted / faint` 위계 그대로 사용.
- 새 색을 도입하기보다 **기존 토큰을 영역 강조에 재배치**.

### D-3. 4영역 색상·아이콘 제안
| 영역 | area_key | 한국어 | 아이콘(예) | 색상 방향 |
|---|---|---|---|---|
| 영적 | spiritual | 영적 | 🙏 / 손모음·빛 | 보라/인디고 (차분·묵상) |
| 지적 | intellectual | 지적 | 📖 / 책·전구 | 블루 (사고·집중) |
| 신체적 | physical | 신체적 | 💪 / 활동·하트비트 | 그린(브랜드 계열) (활력) |
| 사회적 | social | 사회적 | 🤝 / 사람·하트 | 앰버/오렌지 (관계·온기) |

> 색은 채도를 낮춘 파스텔 톤으로 통일해 "따뜻함" 유지. 색맹 고려해 색 + 아이콘 + 라벨을 항상 함께(색만으로 구분 금지).

### D-4. 카드 스타일
- 둥근 모서리(`--radius-card`), 부드러운 그림자(`--shadow-card`), 충분한 내부 패딩(16px).
- 좌측 4px 영역 색 바 또는 상단 아이콘으로 영역 식별.

### D-5. 버튼 스타일
- 1차 버튼: full-width, 높이 ≥48px, 브랜드 그린 배경.
- 2차: 아웃라인/고스트. 터치 타깃 최소 44×44px.
- 기존 `Button` 컴포넌트 variant 재사용(신규 prop은 optional만 추가).

### D-6. 그래프 스타일
- 미니멀(축·격자 최소화), 영역 색과 일치, 숫자 라벨 병기.
- 진행률은 항상 **숫자 + 시각요소** 동반.

### D-7. 모바일 여백·글자 크기
- 화면 좌우 패딩 16px, 카드 간격 12~16px.
- 본문 16px, 보조 14px, 큰 숫자(실행률) 28~32px.
- 하단 탭 높이 56~64px + iOS safe-area(`env(safe-area-inset-bottom)`) 여백.
- 한 화면 정보량 최소화(스크롤 허용, 한 카드 = 한 메시지).

### D-8. 다국어 대응 시 주의사항
- 기존 i18n 구조(ko/en/th, `labels.ts`)를 따른다. **Korean-first**.
- 라벨은 하드코딩하지 말고 라벨 맵 사용. 태국어는 줄바꿈·글자폭이 다르니 버튼 텍스트 고정폭 금지.
- 영역명/상태/관계 유형은 기존 라벨 구조 재사용. **DB enum 값 번역 금지, 표시만 번역.**
- 날짜·요일 표기는 로케일별 포맷터 사용.

| 영역별 세부목표(=오늘 목표 소스) | 영역별 목표 항목 | **`moksilgi_detail_goals`** | ✅ | "오늘의 목표"는 이 데이터 기반 |
| 일일 실행 체크 | 날짜별 영역/목표 완료 여부 | ⚠️ 현재 `moksilgi_monthly_records.daily_checks_json` | ✅ | **가장 큰 과제**: 일 단위 빠른 read/write에 부적합 → `daily_checklist`(또는 `daily_checks`) 테이블 분리 검토 |
| 오늘 기록 | 감사/배움/기도/실행 메모, 공유 | **`daily_records`** | ✅ | reflection/practice/prayer_request 존재. ⚠️**gratitude 필드 없음** → 컬럼 추가 검토 |
| 일일 실행률 | 오늘 완료/대상 수 | 계산값 | ✅ | 저장 불필요(파생). 공용 계산 유틸 권장 |
| 주간 요약 | 요일별·영역별 주간 실행률 | ⚠️ **부재** | 🔶 | 현재 weekly 집계 테이블 없음 → 온더플라이 계산 or `weekly_summary` 신설 |
| 주간 로그(감사/기도/코치 메시지) | gratitude, prayer, message_to_coach, status | **`weekly_logs`** | ✅ | 기존 주간 흐름. 코치 피드백과 연결 |
| 월간 요약 | 영역별 rate, total/average | **`moksilgi_monthly_summaries`** | ✅ | 그대로 사용 |
| 월간 회고 | summary, growth_points, next_month_plan | **`monthly_reflections`** | ✅ | "월간 회고 작성"이 여기에 저장 |
| 연속 실행일(스트릭) | 일일 체크 이력 | 계산값 | ⬜ | 일일 체크에서 파생 |
| 코치 피드백 | feedback_text, encouragement, next_step | **`coach_feedback`** | ✅ | weekly_log 연결. 코치가 작성, 피코치는 읽기 |
| 공개/비공개 구분 | visibility, shared_with_coach | **`daily_records`/`monthly_reflections`** | ✅ | 기존 컬럼 재사용 |
| 날짜·타임존 기준 | 사용자 로컬 날짜 | profile/org timezone, 기본 **`Asia/Bangkok`** | ✅ | 0038 마이그레이션 기본값 확인됨 |
| 코치↔피코치 권한 | 관계 존재·상태 | **`coaching_relationships`** | ✅ | 코치 조회 권한 RLS 기반 |

**핵심 데이터 과제 정리**
1. ⚠️ **일일 체크 저장 구조**: 월 레코드 JSON 안에 있어 "오늘만 빠르게 토글"에 비효율. → 일 단위 테이블 분리가 모바일 UX의 관건(F 2단계, 스키마 변경이라 **승인 필요**).
2. ⚠️ **gratitude(감사한 일)**: daily 레벨 전용 필드 부재. → 컬럼 추가 또는 reflection 통합(승인 전엔 통합 운영).
3. 🔶 **주간 집계 부재**: 주간 리포트는 초기엔 클라이언트 집계, 추후 `weekly_summary` 신설.

> 위 모든 스키마 변경(daily_checklist, gratitude, weekly_summary)은 CLAUDE.md 8·15항에 따라 **실제 작성 전 사용자 승인 필수**. 이 문서는 제안까지만 한다.

## F. 개발 우선순위

**1단계 — 매일 쓰는 핵심 루프 (반드시 먼저)**
- 피코치 전용 모바일 셸 + 하단 5탭 레이아웃(presentational, 기존 라우트 위에 입힘)
- 오늘의 목표(홈) / 오늘 실행 체크 / 오늘 기록 3화면
- 실행률 공용 계산 유틸, Asia/Bangkok 날짜 처리
- 기존 moksilgi/daily_records 데이터에 연결(스키마 무변경 범위 내)

**2단계 — 리포트/그래프**
- 주간 리포트, 월간 리포트(기존 `moksilgi_monthly_summaries` 활용)
- 경량 차트(요일 바, 일자별 라인/히트맵)
- (승인 시) `daily_checklist` 분리·`weekly_summary` 신설로 집계 효율화

**3단계 — 코치 피드백 연동**
- 주간/월간 리포트에 `coach_feedback` 표시, 공유 토글(visibility/shared_with_coach) UX 정비
- 코치 측 조회는 기존 RLS·관계 기반(권한 로직 무변경)

**4단계 — PWA 준비**
- `manifest.json`, 아이콘, 서비스워커, 오프라인 캐시, 홈 화면 설치 배너
- safe-area·단일 컬럼 등 1단계에서 미리 지킨 규칙 활용

**5단계 — 알림/푸시/고급**
- 오늘 체크 리마인더 푸시, 스트릭 격려 알림
- "다음 주 제안" AI 문구, 영적 동반(`spiritual_companion`) 연계 등
